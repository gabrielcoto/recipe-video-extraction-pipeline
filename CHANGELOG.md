# Changelog

## [Unreleased]

### Исправления

- `content: null` от LLM-провайдера — невалидный ответ: повтор по `LLM_MAX_RETRIES`, затем `502 llm_invalid_response`.
- Повтор после пустого ответа не отправляет пустое assistant-сообщение: часть OpenAI-совместимых API отклоняет его с 400.
- Отсутствующий бинарь yt-dlp — `500 downloader_unavailable` (проблема окружения, симметрично с ffprobe), а не `502 download_failed`.
- Сбой загрузки Whisper (офлайн без кэша, битый кэш) — `503 model_unavailable`, как у OCR, а не `500 internal_error`.
- Загрузка Whisper и PaddleOCR потокобезопасна: двойная проверка под `threading.Lock`. Инференс PaddleOCR сериализован отдельной блокировкой: предикторы Paddle не переносят конкурентные вызовы.
- Гонка записи cookies устранена: каждый запуск yt-dlp получает личную временную копию cookiefile, исходник только читается. Монтирование `:ro` и docker secrets снова работают.
- Загрузка свыше `MAX_UPLOAD_BYTES` отклоняется по `Content-Length` до чтения тела; точная граница по `file.size` сохраняется (chunked и заниженные заголовки).
- Ответ платформы без `duration` — `400 video_unreadable`, а не `502 download_failed`: сетевого сбоя не было.
- Ошибка yt-dlp показывает конец stderr с финальным ERROR, а не первые 300 символов с WARNING.
- Транзиторные сбои LLM (обрыв соединения, таймаут, статусы 408/429/502/503/504) повторяются отдельно от повторов схемы.
- Повтор при нарушении схемы несёт предыдущий ответ модели (assistant перед feedback): иначе при температуре 0 попытка повторяет ошибку.
- `WHISPER_LANGUAGE=auto` передаёт `language=None` (автодетект), а не строку «auto», которая падала на валидации.
- Сбой ffprobe/ffmpeg — `media_processing_failed`; `run_media` проверяет код возврата.
- Видео без аудиодорожки даёт пустую расшифровку, рецепт собирается по OCR.
- Непредвиденные исключения возвращают документированный JSON ошибки, а не text/plain; ключ тела — `message`.
- Отсутствующий ffprobe/ffmpeg — `500 media_processing_failed`, а не `400 video_unreadable`.
- OCR на части CPU и в эмуляции падал от oneDNN-джита: `disable_mkldnn()` вызывается явно для каждого предиктора.
- Закреплена зависимость `av>=11,<19`: PyAV 19 несовместим с faster-whisper 1.2.1 (`metadata_errors`).
- Извлечение по URL работает: в образе node 22 — yt-dlp 2026.10+ решает player-challenge YouTube в JS-рантайме и node 18 отклоняет.
- Селектор качества скачивания предпочитает ≤720p mp4; если у источника нет вариантов ≤720p — берёт что есть (вплоть до 1080p), `worst` — последний запас: дефолтный `worst` yt-dlp давал нечитаемые кадры для OCR.
- Единицы вне контракта 1.0.0 не попадают в `unit`: промпт ограничен списком 1.0.0, счётные уточнения («зубчик», `clove`) идут в количество/`note`.
- `scripts/compare_gold.py` сопоставляет ингредиенты по нормализованному имени, а не по индексу: пропуск или лишний ингредиент больше не сдвигает все пары. Свободные поля (`note`, шаги) выводятся из метрики флагами `--skip-notes` / `--skip-instructions`.
- Примеры curl в документации заменены на `scripts/upload.sh`: при отсутствии файла печатает `error: file not found: <путь>` вместо невнятного `curl: (26)`.

### Безопасность

- Проверка адресов против SSRF до метаданных и до скачивания; раздел с ограничениями MVP (DNS-rebinding race, редиректы yt-dlp) — в [architecture.md](docs/architecture.md).
- Проверка `YTDLP_COOKIES_FILE` до вызова yt-dlp: каталог вместо файла (пустое монтирование Docker), нечитаемый файл, не-Netscape формат (JSON-экспорт, UTF-16) — всё отдаётся понятной `download_failed` с подсказкой.
- Cookies аккаунта не коммитятся (`.gitignore` закрывает `cookies*.txt`); обход ограничений платформ не встраивается ([SECURITY.md](SECURITY.md)).

### Настройки

- Все ключевые лимиты и параметры вынесены в переменные окружения (`MAX_VIDEO_SECONDS`, `MAX_UPLOAD_BYTES`, `WHISPER_COMPUTE_TYPE`, `LLM_TEMPERATURE`, `OUTPUT_LANGUAGE`, `YTDLP_PLAYER_CLIENT`, `YTDLP_EXTRACTOR_ARGS`); перечень — в [.env.example](.env.example).
- Сообщения об ошибках и описание API отражают настроенные лимиты, а не жёсткие «100 MiB» и «180 секунд».
- `WHISPER_MODEL` пробрасывается из build-arg в рантайм через `ENV`; предзагрузка моделей full-образа — через build-arg `WHISPER_PRELOAD_MODELS` (по умолчанию `small`).
- Предзагрузка OCR в full-образе идёт через фабрику `src.extractors.ocr._get_reader` — с явным отключением oneDNN.

### Инфраструктура

- Кэши моделей вынесены в именованные docker-тома (`hf-cache`, `paddleocr-cache`, `paddlex-cache`) — переживают `down` и пересоздание контейнера.
- Двойной вызов yt-dlp для URL (метаданные + скачивание): лимит длительности обязан срабатывать до скачивания.

### Документация

- Добавлен [docs/real-testing.md](docs/real-testing.md) — протокол реальной проверки: три типа входа, ручные эталоны, сравнение через `compare_gold.py`.
- Документация приведена к состоянию готовой реализации (убраны упоминания каркаса и `501`); OpenAPI дополнен `empty_file` и `internal_error`.
- Раздел «Безопасность» в [architecture.md](docs/architecture.md); суммарное время запроса с расчётом повторов — в [api_reference.md](docs/api_reference.md) и [faq.md](docs/faq.md), ограничения MVP — в «Известных ограничениях».
- Комментарии в `src/` и тестах — короткие факты; история изменений — в этом файле, не в коде.
- `gap-report.md` и `AI_DECLARATION.md` удалены из поставки; мелкие правки текста и ссылок.

### Контракт

- Добавлен устанавливаемый пакет `fropti-core-contracts` 1.0.0 с JSON Schema, импортируемыми валидаторами и CLI-проверкой; черновые режимы контракта удалены.
- Зафиксированы неизвестные количества и порции, единицы, шаги и источники; `Recipe` разделён с контрактами планировщика и списка покупок.
- Контракт оставлен на 1.0.0, байт-в-байт совпадающим с upstream: добавление единиц в enum обратно несовместимо (валидатор 1.0.0 отвергнет рецепт с «1 cup»).
