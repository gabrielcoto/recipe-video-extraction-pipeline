# Частые вопросы

### Что умеет сервис сейчас?

Пайплайн работает сквозным образом и для URL, и для загруженного файла: проверка длительности, безопасное скачивание, STT, кадры, OCR, сборка рецепта через LLM и валидация общего `Recipe`. `make install && make test` проходит без API-ключей и скачивания моделей — внешние вызовы подменены тестовыми дублёрами. Что автоматические тесты не доказывают — качество распознавания на реальных видео; этот план зафиксирован в [real-testing.md](real-testing.md).

### Какой минимальный `.env` нужен?

Для извлечения рецепта обязательны три переменные: `LLM_API_KEY`, `LLM_BASE_URL` и `LLM_MODEL` (любой OpenAI-совместимый endpoint). Всё остальное имеет рабочие значения по умолчанию и перечислено с комментариями в [.env.example](../.env.example). Для английских видео достаточно `WHISPER_LANGUAGE=en` и `OCR_LANG=en`; для мультиязычных роликов `WHISPER_LANGUAGE=auto` включает автодетект языка речи faster-whisper (это язык входного аудио; язык ответа настраивает `OUTPUT_LANGUAGE` — `auto` означает «язык исходного видео»).

### Можно просто загрузить видео, без ссылки?

Да. Открой `/docs`, выбери `POST /extract/upload`, нажми **Try it out**, выбери файл и нажми **Execute**. Принимается непустой файл до 100 МиБ. Для CLI используй `python -m src.main --file путь/к/видео.mp4`. Оба входа ведут в общий пайплайн, который возвращает валидированный `Recipe` либо структурированную ошибку из [API reference](api_reference.md).

### curl пишет «(26) Failed to open/read local data from file/application» — что это?

Это ошибка на стороне клиента: запрос до сервера не дошёл. В `-F 'file=@путь'` curl не смог прочитать локальный файл, но в сообщении не называет ни файл, ни причину. Проверь, что путь существует относительно текущего каталога (`ls путь`) — реальные MP4 в репозиторий не входят (см. «Почему в репозитории нет трёх MP4»). Обёртка `scripts/upload.sh data/input_videos/tomatoChickpea.mp4` проверяет файл до вызова curl и на пропажу печатает понятное `error: file not found: …`.

### Какие ограничения у входного видео?

Не длиннее `MAX_VIDEO_SECONDS` (по умолчанию 180 секунд включительно) и не больше `MAX_UPLOAD_BYTES` / `MAX_DOWNLOAD_BYTES` (по умолчанию 100 МиБ). При превышении API возвращает `400 video_too_long` или `413 file_too_large` до распознавания: длительность берётся из метаданных платформы для URL и через `ffprobe` для локальных файлов. Кадров на видео не больше `MAX_FRAMES` (12).

### Что делать, если LLM вернула невалидный JSON?

Ответ разбирается и проверяется Pydantic-моделью `Recipe`. При ошибке модели передаётся конкретное нарушение схемы, и запрос повторяется ограниченное число раз (`LLM_MAX_RETRIES`); после исчерпания возвращается `502 llm_invalid_response` — валидация не отключается и запрос не повторяется бесконечно. Поддержка structured output у провайдера помогает формату, но не доказывает достоверность рецепта. Отказ провайдера («refusal»), который у части API приходит как `content: null`, считается невалидным ответом: те же повторы, после исчерпания — `502 llm_invalid_response`, а не 500.

Транзиторные сетевые сбои — обрыв соединения, таймаут и HTTP 408/429/502/503/504 от провайдера или шлюза — повторяются отдельно от повторов схемы: `LLM_NETWORK_RETRIES` попыток (по умолчанию 1) с паузой `LLM_RETRY_DELAY_SECONDS`. Постоянные ошибки (400/401/403/404) не повторяются: сразу возвращается `502 llm_unavailable`. Имейте в виду: «повторы ограничены» относится к каждому слою отдельно, а не к суммарному времени запроса — при значениях по умолчанию перемножение даёт до 6 вызовов LLM по 180 с, то есть до ~18 минут в худшем случае одного синхронного запроса; клиенту нужен собственный HTTP-таймаут с запасом (подробности — [api_reference.md](api_reference.md) и [architecture.md](architecture.md), раздел «Безопасность»).

Официальная справка: [модели Pydantic](https://docs.pydantic.dev/latest/concepts/models/).

### Что делать, если нет звука или текста на кадрах?

Один источник сигнала не обязан присутствовать в каждом видео: без аудиодорожки STT вернёт пустую расшифровку, рецепт соберётся по тексту с экрана (и наоборот). Если ни речи, ни читаемых надписей нет, API вернёт `422 no_usable_content` вместо догадки. Сценарии каждого типа покрыты тестами.

### OCR падает с «could not create a primitive descriptor for a reorder primitive» — что делать?

Это падение oneDNN (MKLDNN) в Paddle 3.x на части CPU и в эмуляции (Rosetta, QEMU, некоторые ВМ). По умолчанию оно уже обходится: каждый предсказатель OCR получает явный `disable_mkldnn()`, а oneDNN ограничен набором инструкций `OCR_MAX_CPU_ISA=AVX2`. Если задавал эти переменные вручную, проверь, что стоит `OCR_ENABLE_MKLDNN=0`; включать oneDNN (`OCR_ENABLE_MKLDNN=1`) имеет смысл только на обычном x86-64 CPU без эмуляции.

### Почему для скачивания по URL нужен Node 22?

yt-dlp решает player-challenge YouTube в JavaScript-рантайме и принимает только node >= 22 (или deno >= 2.3, bun >= 1.2.11). В Docker-образе Node 22 ставится из NodeSource; имя рантайма задаёт `YTDLP_JS_RUNTIME`. Node из репозитория Debian (18.x) считается неподдержанным, и `POST /extract` вернёт `502 download_failed` с сообщением «No supported JavaScript runtime».

### yt-dlp пишет «Sign in to confirm you're not a bot» — что делать?

YouTube ограничил IP-адрес (обычно адрес датацентра или VPN), поэтому просит подтверждение. Это не дефект кода: воспроизведение в браузере с того же IP столкнётся с тем же. Проект сознательно не использует чужие cookies и обход ограничений (см. [SECURITY.md](../SECURITY.md)). Рабочие варианты: повторить позже, запускать с IP с хорошей репутацией или проверить загрузку на разрешённом локальном файле через `/extract/upload`.

### Что делать, если YouTube, Reels или RuTube не отдает видео?

Зафиксируй платформу и причину: доступ, удаление, авторизация, ограничение загрузки или техническая ошибка. Не обещай поддержку платформы по одному успешному URL. Хосты загрузчика ограничены `ALLOWED_URL_HOSTS` (по умолчанию — домены YouTube); добавление платформы — расширение списка плюс отдельная проверка. Для воспроизводимых проверок используй разрешенные локальные файлы и отделяй их от тестов загрузчика.

### Почему в репозитории нет трёх MP4?

Реальные видео не включены: право на распространение исходных роликов не получено. `pasta.json`, `omelette.json` и `salad.json` в `data/expected_outputs/` — синтетические примеры схемы, а не результаты распознавания. Набор для приёмки (три разрешённых видео с ручными эталонами) готовится по [real-testing.md](real-testing.md) и [правилам набора данных](../data/input_videos/README.md).

### Где взять fropti-core-contracts?

Пакет версии 1.0.0 находится в [packages/fropti-core-contracts](../packages/fropti-core-contracts/) и устанавливается командой `make install`. Другие Python-команды устанавливают этот же пакет из checkout или wheel, мобильная команда использует его JSON Schema. Инструкции приведены в [data_schema.md](data_schema.md#подключение-трёх-команд). Не создавай независимую копию моделей; изменения вноси в общий пакет через PR. Публикация во внешнем реестре не выполнена.

### Как проверить JSON перед передачей другой команде?

Запусти `.venv/bin/python -m fropti_core_contracts путь/к/recipe.json`. Код `0` означает соответствие `Recipe` 1.0.0; невалидный файл даёт код `1`. `make test` дополнительно сверяет JSON Schema с моделью, прогоняет три синтетических примера и проверяет одинаковый wire JSON для video extraction, cooking planner / batch cooking и shopping list. Эти проверки подтверждают формат, но не правильность распознавания или бизнес-логику потребителей.

### Почему make test проходит, а извлечение не работает?

Автоматические тесты проверяют публичное поведение, схему и обработку ошибок с подменой внешних вызовов (pytest `monkeypatch`). Они не вызывают реальные Whisper, PaddleOCR, LLM и YouTube, поэтому не доказывают качество распознавания. Для этого нужны реальные прогоны с ручными эталонами — см. [real-testing.md](real-testing.md).

Для работы с HTTP-частью используй официальные руководства FastAPI: [JSON в теле запроса](https://fastapi.tiangolo.com/tutorial/body/) и [тестирование приложения](https://fastapi.tiangolo.com/tutorial/testing/).

### Как тестировать без API-ключей?

Выполнить `make install` и `make test`. Общий пакет уже включён в зависимости; доступ к отдельному репозиторию контрактов не нужен. Тесты используют локальные JSON и подменяют внешние вызовы через pytest `monkeypatch`; ключи LLM, скачивание видео и модели не нужны. Реальные интеграционные проверки запускаются отдельно с ключами из окружения; результаты моков не считаются доказательством качества извлечения.

### Почему Whisper/PaddleOCR не в requirements.txt?

Базовые проверки (`make install`, `make test`) должны проходить без тяжёлых зависимостей и скачивания моделей — так требует рубрика. Поэтому STT и OCR вынесены в отдельный `requirements-ml.txt` (faster-whisper, paddlepaddle, paddleocr, yt-dlp) с установкой через `make install-ml`; full-образ Docker устанавливает эти зависимости при сборке и предзагружает модели. Тесты подменяют внешние вызовы через pytest `monkeypatch` и не требуют ключей или моделей.

### Как проверить пайплайн на реальном видео?

Команды для одного видео:

```bash
make install-ml
.venv/bin/python -m src.main --file data/input_videos/****.mp4
scripts/upload.sh data/input_videos/*****.mp4
```

Последняя команда — curl с проверкой файла: при пропавшем файле она печатает `error: file not found: …`, тогда как голый `curl -F 'file=@…'` отвечает непонятным «(26) Failed to open/read local data» (см. выше).

Полный протокол — подготовка эталонов, промежуточные артефакты, сравнение с эталоном и URL-проверка — описан в [real-testing.md](real-testing.md).

### Нужна ли база данных?

Для сценария «одно видео → один рецепт» она не требуется. Сохранение рецепта и меню — задачи других частей продукта. Добавляй хранилище или очередь только под согласованный сценарий.

### Как безопасно передать ключ LLM?

Используй `.env` локально и секреты окружения при развертывании. В `.env.example` оставляй только названия и плейсхолдеры. Не отправляй ключ мобильному клиенту и не включай его в логи, PR или примеры запросов.
