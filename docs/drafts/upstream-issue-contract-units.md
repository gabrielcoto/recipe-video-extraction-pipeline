## Заголовок issue

**[contract] Добавить `cup`, `oz`, `lb` в enum `Unit` (minor-бамп Recipe 1.0.0 → 1.1.0)**

## Текст issue

### Проблема

Валидатор модуля извлечения видео (video extraction) привязан к списку единиц из `fropti-core-contracts` 1.0.0 (`g`, `kg`, `ml`, `l`, `pcs`, `tsp`, `tbsp`, `pinch`). В кулинарных видео постоянно звучат американские и домашние меры: «1 cup flour», «8 oz cheese», «стакан муки». Так как единицы `cup`, `oz`, `lb` в контракте нет, LLM вынуждена отдавать для таких ингредиентов `quantity: null` и переносить количество текстом в `note`. Для модулей-потребителей это означает потерю структурированного количества: planner не может масштабировать порции, shopping list не может агрегировать покупки по количеству.

Сейчас fork-сервис на время разработки ограничил промпт единицами 1.0.0 (счётные уточнения вроде «зубчик» идут в `pcs` + `note`), но это компромисс: количество в стаканах и унциях по-прежнему уходит в `note`.

### Предложение

Добавить в enum `Unit` три значения и поднять версию контракта до **1.1.0**:

| Значение | Смысл | Коэффициент для потребителей (справочно, контракт не пересчитывает) |
| --- | --- | --- |
| `cup` | Мерный стакан объёма (US cup ≈ 240 мл) | 1 cup ≈ 240 мл по объёму |
| `oz` | Унция массы (avoirdupois) | 1 oz = 28,35 г |
| `lb` | Фунт массы | 1 lb = 453,6 г |

Классификация по правилам `docs/data_schema.md` — **minor**: аддитивное расширение enum'а, все рецепты 1.0.0 остаются валидными. Обратная несовместимость есть у валидаторов: потребитель, знающий только 1.0.0, отвергнет рецепт с `"unit": "cup"`, поэтому миграция обязательна (см. ниже).

### Что сознательно НЕ включается

- `clove`, `slice`, `stick`, `can` — счётные уточнения, а не меры: «3 зубчика чеснока» — это `{"value": 3, "unit": "pcs"}` с `note: "зубчика"`. Считать их отдельными единицами контракта не нужно.
- `fl oz` — жидкие унции редки в целевом контенте; при необходимости добавляются таким же minor-бампом позже.
- Пересчёт единиц в контракте: `cup` → мл для сухих продуктов зависит от плотности, а у shopping list свои правила конвертации; контракт даёт коды единиц, а не величины.

### План миграции (в одном PR)

1. `fropti-core-contracts`: `CONTRACT_VERSION` → `1.1.0`, `Literal["schema_version"]` → `1.1.0`, версия пакета, новый файл `schemas/recipe-1.1.0.schema.json` (генератор `python -m fropti_core_contracts.schema --output ...`).
2. Модуль извлечения видео: обновить валидацию, перевести негативные тесты `cup`/`oz`/`lb` в канонические, расширить промпт LLM.
3. Cooking planner / batch cooking: обновить валидатор и DTO (принимать новые значения `unit`).
4. Shopping list: обновить валидатор и DTO; правила пересчёта в граммы/миллилитры — собственное решение модуля.
5. Мобильный клиент: пересобрать DTO по JSON Schema 1.1.0.
6. CHANGELOG + примеры: существующие примеры в `data/expected_outputs/` остаются на 1.0.0 (валидны для обеих версий).

### Затронутые команды

- Video extraction (инициатор) — продюсер `Recipe`.
- Cooking planner / batch cooking — потребитель `steps` и `servings`.
- Shopping list — потребитель `ingredients` и `servings`.
- Мобильный клиент — потребитель JSON Schema.
