# Черновик контракта 1.1.0 — единицы измерения

Статус: **черновик, не активен**. Пакет `fropti-core-contracts` в репозитории остаётся на 1.0.0 и совпадает с upstream; этот документ — предложение для обсуждения в issue upstream-репозитории. Пока бамп не согласован (ответственная за контракт — Виктория Пугач), промпт LLM ограничен единицами 1.0.0, а `cup`/`oz`/`lb` временно пересчитываются промптом по коэффициентам из таблицы ниже с сохранением исходной формулировки в `note`.

## Что предлагается

Добавить в enum `Unit` три значения:

| Значение | Смысл | Пример из видео |
| --- | --- | --- |
| `cup` | Американский мерный стакан объёма (~240 мл), объёмная мера | "1 cup flour" |
| `oz` | Унция массы (28,35 г) | "8 oz cheese" |
| `lb` | Фунт массы (453,6 г) | "2 lb chicken" |

Классификация изменения — **minor** по правилам [data_schema.md](../data_schema.md#версии-и-изменения): старые рецепты остаются валидными, но валидаторы потребителей на 1.0.0 отвергнут рецепты с новыми единицами, поэтому план миграции обязателен (planner и shopping list обновляют схемы/DTO; мобильный клиент берёт новую JSON Schema).

## Почему только три значения

Первоначальный вариант расширял enum восемью значениями (`cup`, `fl oz`, `oz`, `lb`, `clove`, `slice`, `stick`, `can`). Сокращение:

- `clove`, `slice`, `stick`, `can` — счётные уточнения, а не меры: «3 зубчика чеснока» выражается как `{"value": 3, "unit": "pcs"}` с `note: "зубчика"`, «1 пачка масла» — `{"value": 1, "unit": "pcs"}`, note «пачки масла». Правило уже действует в промпте LLM и не требует изменений контракта.
- `fl oz` (жидкие унции) встречается редко и в русских видео почти не звучит; до появления реальных примеров выгоды от нового значения меньше стоимости миграции. При необходимости добавляется тем же minor-бампом позже.

## Чего контракт по-прежнему не делает

Пересчёт единиц остаётся за потребителями: `cup` → миллилитры требует объёма конкретного стакана, `oz`/`lb` → граммы — детерминированные коэффициенты (28,35 и 453,6), но пересчёт нельзя «молча» зашивать в контракт — у shopping list свои правила конвертации. Значения `unit` остаются кодами, а не величинами.

## Что входит в бамп при одобрении

1. `CONTRACT_VERSION` и `Literal["schema_version"]` в `models.py` → `1.1.0`, версия пакета в `pyproject.toml`.
2. Новый файл схемы `schemas/recipe-1.1.0.schema.json` (генерируется `python -m fropti_core_contracts.schema --output ...`; старый файл 1.0.0 остаётся в репозитории для валидации старых данных).
3. Три JSON-примера в `data/expected_outputs/` остаются на 1.0.0 (валидны для обеих версий); негативные тесты с `cup`/`oz`/`lb` переводятся из «невалидные» в «канонические».
4. Промпт LLM (`src/llm/fusion.py`): добавить три единицы в список; английские "1 cup"/"8 oz"/"2 lb" нормализуются в новые коды, русское «стакан» остаётся в `note`, потому что объём русского стакана (200–250 мл) ≠ US cup (240 мл).
5. Обновление валидаторов/DTO planner и shopping list в их репозиториях, запись в CHANGELOG, подтверждение Виктории Пугач в PR.

## История вопроса

«1 стакан воды» из речи нельзя было выразить контрактом 1.0.0 — ингредиент уходил из LLM с `quantity: null`. Первая попытка решения (бамп 1.1.0 с восемью единицами в форке) была отозвана: менять общий контракт без согласования нельзя, потребители и мобильный клиент остаются на 1.0.0 (см. [текст issue](upstream-issue-contract-units.md)).
