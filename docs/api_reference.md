# API reference

Базовый адрес при локальном запуске: `http://localhost:8000`. Интерактивная документация — `/docs`, машиночитаемая схема — `/openapi.json`.

## GET /health

Проверяет доступность приложения и сообщает версию общего контракта.

```http
GET /health
```

```json
{"status": "ok", "contract_version": "1.0.0"}
```

Этот endpoint не проверяет доступность видеоплатформ или моделей.

## POST /extract

Принимает **JSON в теле запроса**, а не query-параметр.

```bash
curl -i -X POST http://localhost:8000/extract \
  -H 'Content-Type: application/json' \
  -d '{"url":"https://www.youtube.com/shorts/EXAMPLE_ID"}'
```

| Поле | Тип | Обязательность |
| --- | --- | --- |
| `url` | Строка, корректный HTTP/HTTPS URL | Да |

`EXAMPLE_ID` служит плейсхолдером. Синтаксически допустимый URL не гарантирует поддержку платформы или доступность видео.

Поддержка URL ограничена одной согласованной платформой: хосты YouTube (`youtube.com`, `www.youtube.com`, `m.youtube.com`, `youtu.be`, `music.youtube.com`). Список настраивается переменной окружения `ALLOWED_URL_HOSTS`. Другие хосты отклоняются с `400 unsupported_platform`. Загрузчик проверяет схему URL, разрешает DNS и отклоняет адреса, указывающие на частные, loopback или link-local сети (`400 ssrf_blocked`). Проверка выполняется для исходного хоста и до обращения к платформе; известные ограничения проверки (пере-разрешение DNS и редиректы уже внутри yt-dlp) описаны в [architecture.md](architecture.md), раздел «Безопасность». Длительность запрашивается через метаданные платформы до скачивания (`yt-dlp --skip-download`) и до любых этапов распознавания.

## POST /extract/upload

Принимает видеофайл в **multipart/form-data**, поле `file`. В Swagger UI (`/docs`) нажми **Try it out**, выбери файл и нажми **Execute**.

```bash
curl -i -X POST http://localhost:8000/extract/upload \
  -F 'file=@data/input_videos/pasta.mp4'
```

Файл `pasta.mp4` пока не включен в репозиторий: сначала добавь разрешенное видео или замени путь своим. Не задавай `Content-Type` вручную: клиент добавит multipart boundary.

| Поле | Тип | Обязательность |
| --- | --- | --- |
| `file` | Непустой файл до 100 МиБ включительно | Да |

Сервис сохраняет файл во временную папку под собственным именем, передает путь общему пайплайну и очищает папку после запроса, в том числе при ошибке. Длительность определяется через `ffprobe`; файл, который не является читаемым видео, отклоняется до распознавания (`400 video_unreadable`).

## 200 OK — успешный ответ обоих эндпоинтов

Ответ — сам объект `Recipe`, без дополнительной обёртки. API и OpenAPI используют модель из `fropti-core-contracts` 1.0.0. [Описание схемы](data_schema.md) и [JSON Schema](../packages/fropti-core-contracts/schemas/recipe-1.0.0.schema.json) едины для всех команд. Пайплайн: длительность (до тяжёлых этапов) → STT речи (faster-whisper) → равномерный выбор кадров → OCR (PaddleOCR) → LLM собирает `Recipe` → валидация моделью `Recipe` 1.0.0.

Для `POST /extract` источник устанавливается как `{"type": "url", "url": "<исходный URL>"}`; для загрузки и CLI-файла — `{"type": "upload"}`. Источник ставит сервер из реального входа, а не LLM. `{"type": "manual"}` предназначен для ручного ввода в других модулях; эндпоинты извлечения его не создают.

Синтетический пример формата (не результат распознавания):

```json
{
  "schema_version": "1.0.0",
  "title": "Омлет",
  "servings": 1,
  "ingredients": [
    {"name": "Яйца", "quantity": {"value": 2, "unit": "pcs"}, "note": null},
    {"name": "Соль", "quantity": null, "note": "По вкусу"}
  ],
  "steps": [
    {"instruction": "Взбейте яйца с солью.", "duration_seconds": null},
    {"instruction": "Приготовьте омлет на сковороде.", "duration_seconds": null}
  ],
  "source": {"type": "url", "url": "https://www.youtube.com/shorts/EXAMPLE_ID"},
  "total_time_minutes": null
}
```

## Ошибки

| HTTP | Код | Условие |
| --- | --- | --- |
| `400` | `video_too_long` | Длительность больше 180 секунд; проверка до STT/OCR |
| `400` | `video_unreadable` | Локальный файл не является читаемым видео, длительность недостоверна или платформа не сообщила длительность URL-видео |
| `400` | `unsupported_platform` | Хост URL вне `ALLOWED_URL_HOSTS` или схема не HTTP/HTTPS |
| `400` | `ssrf_blocked` | Разрешение DNS дало частный, loopback, link-local или иной запрещённый адрес |
| `400` | `empty_file` | Загружен пустой файл |
| `413` | `file_too_large` | Загруженный файл больше 100 МиБ |
| `422` | `no_usable_content` | Нет ни распознанной речи, ни читаемого текста с экрана; догадка вместо рецепта запрещена |
| `422` | стандартный `detail` FastAPI/Pydantic | Нет `url`, неверный тип, URL или JSON; нет поля `file` при загрузке |
| `500` | `media_processing_failed` | ffmpeg/ffprobe не смогли обработать файл |
| `500` | `ocr_failed` | OCR упал на кадрах после успешной загрузки модели |
| `502` | `download_failed` | Платформа недоступна или файл не скачался: yt-dlp не смог получить метаданные или скачать видео |
| `502` | `llm_unavailable` | LLM не настроена, недоступна (сетевые повторы исчерпаны) или вернула постоянный HTTP не 200 |
| `502` | `llm_invalid_response` | После всех повторов LLM не вернула JSON, проходящий валидацию `Recipe` |
| `503` | `model_unavailable` | Модель STT/OCR не установлена в окружении сервиса |
| `500` | `internal_error` | Непредвиденная прикладная ошибка; подробности в логах сервиса |

180 секунд допустимо; 180.1 секунды — уже превышение. Проверка происходит до тяжелого распознавания.

Структура прикладной ошибки:

```json
{
  "detail": {
    "code": "video_too_long",
    "message": "..."
  }
}
```

`message` предназначен для человека; клиент должен ориентироваться на HTTP-статус и `code`. Ответ `422` на ошибки валидации тела использует стандартный список ошибок FastAPI в `detail` и не имеет такой структуры.

Если видео короче лимита, но скачанный файл оказался больше `MAX_DOWNLOAD_BYTES`, скачивание прерывается с `502 download_failed`. Ограниченные повторы LLM происходят внутри пайплайна с конкретной обратной связью о нарушениях схемы; число повторов задаётся `LLM_MAX_RETRIES` (по умолчанию 2, итого до 3 попыток). Транзиторные сетевые сбои (обрыв соединения, таймаут, HTTP 408/429/502/503/504) повторяются отдельно: `LLM_NETWORK_RETRIES` попыток (по умолчанию 1) с паузой `LLM_RETRY_DELAY_SECONDS`; постоянные ошибки (400/401/403/404) не повторяются и сразу возвращают `502 llm_unavailable`.

## Ограничения интеграции

API не реализует аутентификацию, квоты, очередь задач и сохранение результатов. Не публикуй его как готовый публичный сервис. Мобильный клиент отправляет ссылку или файл серверу; он не запускает Python-код и не получает серверные API-ключи. Обработка синхронная; три реальных сквозных прогона описаны в [evaluation.md](evaluation.md).
