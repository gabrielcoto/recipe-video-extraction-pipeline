# План реализации MVP (10–12 часов)

Извлечение реализовано: длительность, безопасная загрузка, STT, кадры, OCR, объединение через LLM и обработка ошибок работают и покрыты тестами (`make test`). Пункты 2 и 10 остаются: они требуют реальные видео, ручные эталоны и сквозные прогоны. Критерии готовности приведены в [рубрике](../docs/evaluation.md).

1. [x] Изучить подключённый `Recipe` 1.0.0, валидатор и JSON Schema в `packages/fropti-core-contracts/`; использовать их в промпте LLM и интеграциях без создания отдельной модели.
2. [ ] Подготовить минимум три разрешённых реальных видео и ручные эталоны в `data/`; зафиксировать нормализацию и набор оцениваемых полей до прогона. План — в [docs/real-testing.md](../docs/real-testing.md).
3. [x] Реализовать безопасное получение метаданных URL и файла в `downloader.probe_duration`; отклонять видео длиннее 180 секунд до тяжёлых этапов.
4. [x] Реализовать `downloader.download_video` с защитой от SSRF, ограничениями размера и времени; использовать временные файлы с очисткой. Проверку редиректов yt-dlp не реализовали — остаточный риск зафиксирован в [architecture.md](../docs/architecture.md), раздел «Безопасность».
5. [x] Реализовать извлечение аудио и STT в `extractors/stt.py`; закрепить модель, параметры и требования к ресурсам.
6. [x] Реализовать выбор кадров в `extractors/frames.py` и OCR в `extractors/ocr.py`; определить частоту кадров и ограничения ресурсов.
7. [x] Реализовать объединение STT/OCR через LLM в `llm/fusion.py`, валидацию общего `Recipe` и ограниченные повторы без выдумывания отсутствующих данных.
8. [x] Соединить этапы в `pipeline.py` для URL и локального `Path`, сохранив работающие точки входа и очистку временных данных при успехе и ошибке.
9. [x] Согласовать и реализовать обработку ошибок этапов в `api.py` и `main.py`; обновить API-документацию, Postman и пример клиента по фактическому поведению.
10. [ ] Дополнить тесты публичного поведения без API-ключей, выполнить `make test`, отдельно провести реальные сквозные проверки и приложить результаты по рубрике.

Все десять пунктов относятся к обязательному MVP. Для URL достаточно одной согласованной платформы и трёх воспроизводимых видео; локальная загрузка остаётся обязательной. Поддержку нельзя объявлять по одному частному успешному URL.

## Бонусы после MVP

- [ ] Добавить и отдельно протестировать другие платформы (YouTube Shorts, Reels, RuTube), не используя приватные cookies или обход ограничений доступа.
- [ ] Измерить задержку и ресурсы, затем при необходимости спроектировать отдельный асинхронный API заданий.
- [ ] Добавить GPU-профиль, кэширование или публикацию `fropti-core-contracts` только с воспроизводимой установкой и версионированием.
- [ ] Интегрировать сохранение, UI или каталог продуктов в отдельных модулях, не расширяя ими `Recipe` 1.0.0.
